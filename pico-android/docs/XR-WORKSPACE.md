# PICO XR 空间工作区（Vision Pro 风格）

本文说明 PICO 原生 OpenXR 客户端的“空间工作区”布局。它参考 Vision Pro 的
Mac 虚拟显示器与空间窗口体验：屏幕保持在视线正前方、按需环绕、可整体重定位、
记住上次选择；不复制 Vision Pro 的窗口管理器，也不改变 UU 远控协议。

## 用户操作

XR 工具栏 →「空间」→「空间布局」：

| 行 | 行为 |
| --- | --- |
| 工作区布局 | 自动 → 并排 → 环绕循环切换，选中即重排 |
| 观看距离 | 近 1.6 m / 标准 2.2 m / 远 3.0 m 循环切换，选中即重排 |
| 重定位到眼前 | 把整组窗口刚性移到当前视线正前方并恢复到所选观看距离，保持尺寸与相对布局 |
| 重新排列窗口 | 按当前布局与距离重新摆放，用于清除手动拖动后的位置 |
| 重置窗口位置 | 恢复默认尺寸与位置（原“重置空间布局”语义） |

布局与距离写入 `xr_workspace` SharedPreferences，下次进入沉浸式会话时自动应用。

### 三种布局

- **自动**：1–2 块屏幕用平面并排；3 块及以上用环绕。默认值。
- **并排**：所有可见屏幕保持在同一平面，按真实宽高比例排列。
- **环绕**：屏幕沿以最近一次显式排布时的头部位置为圆心的圆柱排布，每块屏幕到该
  圆心的距离一致，减少侧屏因斜视造成的压缩；总水平弧度限制在 120°，超出时圆柱半径
  增大而不是把屏幕推到视野外。走动后点“重定位到眼前”会把整组窗口搬回当前视线并
  恢复到所选距离。

### 主屏优先

每行 3 个槽位中，槽位 0（第二行是槽位 3）是主屏。每次显式排布时主屏位于当前视线
正前方，其余屏幕依次放在主屏右侧、左侧；这与双屏/三屏实体办公桌的习惯一致。
主屏不可用时，该行剩余屏幕作为整体居中，不会被推到任意一侧。第二行槽位 3–5 只在
运行时合成层预算足够时才存在（`maxLayerCount` ≥ 10 左右）；层数不足时只有
第一行三块桌面，自动/并排/环绕对它们仍有效。

## 几何实现

纯函数位于 `app/src/main/cpp/xr_workspace.h`，渲染循环只负责取头部姿态并调用：

- `workspace_layout(panels, visible_mask, distance, mode, anchor = {})`：按两行三列
  排布可见屏幕。`anchor` 是最近一次显式排布时的头部位姿（默认 `{}` 表示会话原点）；
  自动重排沿用上次锚点，显式切换布局/距离/重新排列/重定位会用当前头姿重建。平面模式
  保持真实宽高与 100 英寸上限；环绕模式把屏幕中心放到半径
  `max(distance, 半宽 / sin(60°))` 的圆柱上，屏幕朝向由每帧的
  `panel_face_user` billboard 保持面向眼睛。
- `workspace_recenter(panels, visible_mask, head, distance)`：绕用户旋转整组窗口，
  使其质心方位与视线一致，再沿视线整体平移到配置距离，并把质心放到略低于眼睛的
  高度；尺寸和两两间距不变（走动后不会贴脸或落在身后）。极宽且明显偏侧的组会限制
  拉近量，保证最近的屏距眼睛至少 40 cm；触发该保护时实际距离会大于所选档位。
- 上层槽位（3–5）始终叠放在下层上方，不重叠；只有上层可见时它居中在眼高。

自动重排由以下事件触发：打开/关闭空间窗口、窗口真实宽高变化、工具栏缩放 ±6%、
切换布局/距离、重置。切换布局/距离、重新排列、重定位会以当前头部位置重新锚定；
打开/关闭窗口、宽高变化和 ±6% 缩放沿用上次锚点，因此重定位后不会跳回会话原点。
用户一旦实际移动或缩放某块屏幕（仅按下抓取条、或按下后未移动都不算），就进入
“手动覆盖”，后续自动重排不再移动整组窗口；点「重新排列窗口」或「重置窗口位置」
恢复自动排布。拖动与缩放本身仍按原有交互工作。

已知限制：从明显偏侧/侧后方重定位后，整组朝向与当前视线可能仍有偏差；下一次自动
重排会把整组摆正，侧屏可能移动甚至左右换位（正后方走动时通常无感）。需要精确保持
位置时，重定位后先不要触发重排，或重新选择一次布局/距离。

## 与既有功能的关系

- 跟随视角（VIEW 跟随）保持不变：工作区在跟随参考空间内排布。
- 每屏的“设置”菜单仍锚定在该窗口上方；布局重排后菜单在下一帧跟随。两行布局时
  菜单可能压在上层窗口上（菜单层最高且有命中优先级），这是既有菜单锚定策略的限制。
- 单屏仍受对角线 100 英寸（2.54 m）上限约束；布局不会突破该上限。
- 环绕布局在窗口总宽过大时会自动后移以保持在 120° 视野内，因此“近”档在
  三块大屏时可能比标称距离更远；单屏/双屏仍按所选距离摆放。这是为了让整组屏幕
  保持在舒适视野内的取舍，不是精确测距。
- 空间布局页共 12 行，每页显示 6 行；手柄摇杆可翻页，射线/触摸用户只能点到当前页。
  缩小/放大和重置窗口位置在串流设置页也有入口，因此不影响这些操作的可达性。
- 本功能只属于 OS 5/OpenXR 客户端；OS 6 Spatial SDK 预览后端不在本次范围内。

## 测试与验证

本地已执行：

```bash
# 原生布局/重定位单测（CI 也会执行）
c++ -std=c++17 -Wall -Wextra -Werror -Ipico-android/app/src/main/cpp \
  pico-android/app/src/test/cpp/xr_workspace_test.cpp -o /tmp/xr-workspace-test
/tmp/xr-workspace-test

# JVM 模型单测（设置类只做 SharedPreferences 读写，未单测；系统默认 JDK 27 会让 AGP jlink 失败，需 JDK 17）
cd pico-android
JAVA_HOME=/usr/lib/jvm/java-17-openjdk gradle --offline --console=plain \
  :app:testDebugUnitTest :app:assembleDebug :app:compileDebugAndroidTestKotlin
```

结果：原生测试通过；JVM 测试 328 项通过（含并行新增的无关测试）；arm64 debug APK 构建通过，且
`libopenuuyc_pico.so` 中存在 `nativeSetWorkspace` / `nativeApplyWorkspace` /
`nativeRecenterWorkspace` 符号。

**未在 PICO 实机验证**：120° 环绕的实际佩戴观感、重定位恢复距离后的颈部舒适度、
双/三屏真实出图下的对称性、菜单锚定与手势冲突都需要按
[真实硬件验收矩阵](../HARDWARE-TESTING.md) 的 W1–W5 项确认。构建和单测通过
不能当作硬件验收。
