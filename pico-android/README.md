# OpenUUYC PICO — UU 协议直连开发版

## 架构

原生 Android APK 自主运行以下代码：`UuNrdApi.kt`（匹配桌面端 `src/account/api/mod.rs` 的 NRD REST/HMAC 和二维码登录）、`UuWire.kt`（Socket.IO v4、控制握手、UU protobuf ConnectOptions/ECHO、gzip SDP）、`UuDirectSession.kt`（原生 Android libwebrtc / UU DataChannel、ICE、视频接收、原生指针输入），以及 `xr_client.cpp`（PICO OpenXR/GLES 双眼空间四边形层）。

PICO 在本机进行 UU 登录，获取设备列表和加入房间；**不需要运行 Linux OpenUUYC、不经过本机 WebSocket 桥接、无需 ADB reverse**。Android 和 PICO 头显本身通过 UU Socket.IO WebRTC 向被控主机连接。

请注意：这里是 *协议实现开发版*，编译通过不代表已经与真实 UU Windows/Linux 主机完成互操作测试。

## 使用

1. 在 Actions 的 `PICO Android OpenXR` 工作流下载 arm64 debug APK，安装到 PICO。
2. 连接互联网，打开应用，点击「使用 UU 二维码登录」，使用另一台设备的 UU 客户端扫码确认。
3. 设备列表展示在线、可被控且无占用的设备；选择目标后将直接请求 NRD 房间，执行原生信令与 WebRTC 连接。
4. 默认在普通 Android 窗口中显示远程桌面，可点击、拖动和使用滚轮；不会自动进入沉浸式。只有显式点击设备卡片的「沉浸式连接」，才会启动 OpenXR，使用手柄瞄准和扳机控制。

## CI

工作流 `.github/workflows/pico-android.yml` 包含 JVM 协议单测、Android Lint、arm64 JNI/OpenXR 构建和 Linux 对照端检查。Actions **无法模拟真实 UU 服务和 PICO 追踪环境**。QR 账号有效性、信令握手顺序、H264 播放和鼠标真正控制远端机器仍需要物理头显与主机双端联测。

## 可靠性与输入

- UU 房间的多个已授权信令节点支持**命名空间建立前**的自动切换；连接建立后不重放可能改变远端状态的请求。
- 房间控制握手 30 秒、WebRTC ICE 35 秒超时会终止失效会话；发送采集请求 25 秒无首帧仅告警，避免主机短暂停止输出被强制断开。
- 二维码确认后会强制刷新设备注册；轮询间隔 1 秒，重入登录与旧会话回调不会覆盖当前连接。
- PICO 4 / 4S / Neo3 手柄摇杆 Y 轴触发滚轮事件（120 单位，120ms 节流，45% 死区）；头显失焦、停止运行、屏幕切换时释放远端按键。
- 远端音频使用 Android WebRTC 接收，获得音频焦点才启用音轨；音频焦点丢失会停止播放。


### SDP / ICE / 数据通道完整性

- 等待 UU 原生控制 ACK 后生成 WebRTC Offer；本地 ICE Candidate 在完整 Offer（二进制 gzip 附件）已入队后发送，远端候选则等待 SDP Answer 安装成功。每个方向最多保留 128 个待处理候选，重复项合并，旧会话候选在退出时清理。
- 按桌面协议创建 1 条音频及 5 条独立接收视频 m-line。根据 Answer 中未被拒绝（端口非零）的轨道构建 `SendVideoTrack` 注册列表，不抢先在 SDP 安装前发起视频注册。
- 收到匹配的 `SendVideoTrackRsp` 后才请求视频采集；5 秒无注册 ACK 或控制通道断开会结束失效的会话。
- 远端屏幕切换后重新选择 `video_N` 对应的渲染轨道，不允许迟到的其他轨道覆盖当前画面。
- 遥控鼠标松开优先于位置移动消息。在背压、屏幕切换、XR 失焦与通道关闭情况下尽力释放；释放入队失败则关闭会话，不继续发送控制输入。
- ICE 首次建立最多等待 35 秒，已连接后断线提供 15 秒恢复窗口；如未恢复则关闭失效连接。上述行为有独立 JVM 回归测试，尚须 PICO 设备/UU 主机真实联测。

## 安全

NRD 登录只请求 https；信令仅使用 wss；应用通过 `usesCleartextTraffic=false` 禁止明文网络。授权令牌通过 Android Keystore 的非导出 AES-256 密钥与 AES-GCM 加密，密文仅保存于应用私有存储，不写日志、不提供明文回退。正常退出、进程重启或头显重启后自动恢复并调用 UU 用户接口校验；网络故障保留密文并提供重试，服务明确返回凭证失效或主动本机退出时清除。本实现仅提供已登录且可控设备的正常远程控制，不自动接管已有会话。

保留的 Linux `pico_bridge.rs` 仅作为旧实验性桥接方案，不再是原生 APK 的默认架构。

## 测试与验收

所有 JVM 协议测试在无生产 UU 账号的 CI 中运行；包括协议格式、QR/NRD、Socket.IO、ICE 时序、视频轨道绑定、WebRTC 状态与鼠标输入背压等测试类。CI 自动保存 XML/HTML 报告，即使单测失败也可以在 Actions Artifacts 中定位具体断言。

- **自动测试**：HMAC 签名的时间、HTTP 方法、路径、请求体、设备身份绑定；MockWebServer 上的真实 HTTP 请求、身份作用域、拒绝重定向、脱敏、4 MiB 响应限额。
- **协议回归**：UU Socket.IO ACK、protobuf ECHO、视频轨道 ACK、屏幕 ID 与轨道绑定、SDP 重写/gzip、异常 protobuf 和有界随机输入。
- **状态机回归**：只允许 CONTROL 通道完成 PB 握手，ACK 必须匹配请求序号，收到轨道成功 ACK 才能请求采集；切换显示器/断线立刻撤销输入权限。
- **实机基础冒烟**：连接 PICO USB 调试后运行 `bash pico-android/scripts/pico-adb-smoke.sh [debug.apk]`，检查安装、Activity 启动、进程存活与崩溃日志。该脚本不等于 UU 账号、ICE、视频及手柄端到端测试。
- **实机端到端验收**：依照 `pico-android/HARDWARE-TESTING.md` 对照真实 UU 被控主机逐项检查。

当前未提供可公开的 UU 测试账号、远端机器和 PICO 设备，CI 无法验证真实远程控制成功。请勿把纯协议测试通过等同于能生产使用。

## 多窗口（PICO OpenXR）

PICO 原生客户端目前按 XR runtime 支持的合成层上限创建**最多 3 个独立空间面板**：中间为 UU 当前选择的屏幕轨道，左右分别绑定其他已解码且确实存在的 `video_N` 轨道。每个面板都有独立的 Android Surface、WebRTC EglRenderer、OpenXR Surface Swapchain；空间定位器按面板命中计算鼠标坐标。没有对应视频轨道时不显示空白面板；不将重复 RTP 轨道当成新窗口。

仅使用 UU `ScreenSources` 明确返回的 `screen_id ↔ video_track_index` 映射控制侧窗；映射未知的侧窗只能观看，不能将鼠标输入错误发送到默认显示器。跨窗移动、失焦时释放按键；本实现暂不保证 UU 主机真的同时推送多个视频轨道，需真实双/三屏主机测试。

## PICO 4 Ultra 相机接口与权限

已补 Android `CAMERA` 按需权限请求（不再安装即索要）、Camera2 设备枚举与主动预览入口；打开预览后，若系统不公开 Camera2 ID，应用显示设备不支持的具体原因而不是无响应。页面可缩放，预览失焦/切换应用后会关闭摄像头释放资源。

**PICO 4 Ultra 透视彩色相机不保证暴露为 Android Camera2**：消费版 PICO 的 XR 透视摄像头须经 PICO SDK 对应的专用 XR 相机扩展与平台权限才能获取。当前 Camera2 代码是可用设备的预览路径和错误诊断，**不是** `XR_PICO_camera_image` 透视相机接入的替代品。未经真实头显验证前不得视为原生透视取流修复完成。

## PICO 4 Ultra 视频透视（MR 背景）

在设备列表上方「现实透视背景」切换开关。默认尝试使用 Android OpenXR runtime 所公开的 `XR_ENVIRONMENT_BLEND_MODE_ALPHA_BLEND`，把系统渲染的实时环境作为空间窗口后的背景；如果 PICO 固件不支持，则回退到不透视的 VR 背景，不影响控制链路。这与 Camera2 图像读取是两回事：合成器掌握图像，应用本身不获取原始相机帧。该方案参考 PICO 官方视频透视文档，仍需 PICO 4 Ultra 实机确认 alpha-blend 与 quad-only 场景能协同渲染。

若业务确实要求读取摄像头原始帧用于本地计算机视觉，应另行实现 PICO Native OpenXR 3.0 `XR_PICO_camera_image`（依赖 `XR_EXT_future`）或 SecureMR 授权数据通路，并处理运行时能力、设备版本、摄像头占用、异步 Future 生命周期与个人信息权限；`Camera2` 的成功仅代表该固件确实暴露了 Android 摄像头，并非原始透视传感器的保证。

## PICO 启动显示

登录、二维码和设备列表使用普通 Android 面板 Activity；选择设备后才进入独立的 OpenXR 沉浸式 Activity。不要给登录 Activity 添加 `pvr.app.type=vr` 或 `IMMERSIVE_HMD`：PICO 会跳过普通 View 绘制，造成启动黑屏。房间授权仅通过进程内一次性对象交接，不放入 Intent、磁盘或日志。

## Linux 风格控制中心与登录恢复

- 配色、圆角、侧栏宽度、二维码尺寸取自 `src/ui/theme.rs`；品牌图片直接复用 `assets/icon-256.png`。`scripts/tests/test_desktop_theme.py` 防止两端样式漂移。
- 登录页使用居中双栏卡片。PICO 尚未实现短信登录，右栏明确展示连接说明，不提供占位短信表单。
- 登录后进入左侧导航（我的设备 / 连接设置 / 关于），支持名称搜索、在线筛选、在线优先/名称排序及设备卡片。离线、不可控、已占用的电脑禁止直接连接。
- 窗口缩放只重排视图，不重建 Activity 或丢弃登录；透视和 Camera2 预览保留在连接设置页，进入 XR 前释放 Camera2。
- 旧版本从未持久化过凭证，首次升级仍需扫码一次；之后启动时自动验证已保存的登录。卸载应用或清除应用数据会失去密钥/凭证，需要重新登录。
- 断网、HTTP 5xx、临时密钥读取失败不会静默删除登录；明确 HTTP 401 或与桌面端相同的失效码 1001/1002/1120 才自动清除。主动「退出登录」删除本机加密凭证，不退出其他设备。
- 加密方式依据 [Android Keystore 官方文档](https://developer.android.com/reference/android/security/keystore/KeyGenParameterSpec)，不承诺每台设备都采用硬件后端；实际持久化与篡改拒绝通过独立的头显进程测试。

### 设备上的 UI / Keystore 验证

构建 `:app:assembleDebug :app:assembleDebugAndroidTest` 后运行 `bash pico-android/scripts/pico-adb-ui-tests.sh <app.apk> <test.apk>`。

测试使用明确标注的虚构账号/设备，**不使用真实 UU 授权**。UI 渲染、筛选、导航与重排使用 Android 真实控件；Keystore 的 save/restore 分两次 instrumentation 进程运行，验证密文不含明文、随机 IV、跨进程恢复和篡改拒绝。结果不能代替实际账号恢复、视频帧、输入、相机和多屏验收。

WebRTC 资源销毁遵循 [PeerConnection 官方回调约束](https://webrtc.googlesource.com/src/+/refs/heads/main/sdk/android/api/org/webrtc/PeerConnection.java)：观察者回调只立即撤销会话，实际资源释放排到主线程，并且不在持有会话锁时等待 WebRTC 原生线程。该防护不等同于真实视频链路已验收。

## 默认普通窗口控制

「远程连接」始终使用可缩放的 `PanelViewerActivity`，没有 VR 元数据、没有 OpenXR 线程。它以 SurfaceView 接收同一原生 UU 视频流，保持视频纵横比，并将实际视频区域的触摸/鼠标位置归一化后发送给远端；失焦、取消与断开时释放按键，支持鼠标滚轮。Surface 重建只重绑渲染目标，不重新注册账号或创建第二个 UU 会话。

OpenXR 仅由独立的「沉浸式连接」按钮显式启动。它是可选模式，不会因重启/恢复登录、普通连接或相机/透视设置自动开启。普通窗口目前仅展示主视频轨道；多面板保留在可选的沉浸式模式。

### 沉浸式工具栏与空间布局（2026-10-27）

- 工具栏使用独立 Android Surface OpenXR quad，通过合成器显示，不依赖在 VR Activity 内不可见的普通 Android 弹窗。支持参数轮换：双方能力内的帧率、画质、码率、光标、编码、缩放尺寸，以及屏幕切换。标签显示已确认值；请求待 ACK 时不更新为成功。
- 点击“拖动 / 缩放”进入布局编辑，扳机拖动所指桌面，摇杆上下缩放，点击“完成布局编辑”恢复远程操作。编辑模式禁止向远端发送拖动/滚轮，缩放范围 0.4–4 米；“重置布局”恢复位置。多屏沿用真实独立视频轨，最多三个桌面，不复制单个轨道冒充多个显示器。
- 运行时按层数预算优先保留主桌面和工具栏，其余最多两个独立桌面。工具栏需要运行时至少支持两个合成层。
- “创建虚拟屏”明确确认后发送 UU 原生 CreateVirtualDisplay RPC（1920×1080 / 一个）。受对端 capture level 和屏幕类型/数量限制；处理错误 ACK、10 秒超时，只有收到新增虚拟屏状态才报告创建完成。实际是否可用取决于远端虚拟显示驱动/权限。
- 已占用设备可点“抢占连接”或沉浸式连接；二次确认后才发送 `force_join=true`，正常连接始终为 false。

这些新增 XR 交互已构建并部署，尚待真人佩戴验证射线命中、布局手感、多屏同时出图和远端虚拟屏/抢占。JVM/设备 fixture 不是这些端到端结果的替代。PICO 作为原生 UU 被控端的屏幕捕获/辅助功能服务尚未实现。

### 模拟窗口交互更新

取代上述“布局编辑开关”：现在桌面内容区始终远控，窗口标题栏和底部抓取条用于移动，抓取时手柄转向进行水平旋转，右下角拖动缩放（0.4–4 米）。工具栏首项改为“跟随视角”，通过 OpenXR VIEW/LOCAL 参考空间切换；默认仍固定于空间。框架是应用内仿 PICO 交互，不是调用 PICO 系统窗口管理器。

编码默认使用 UU `codec_type=0` 自动模式，设置校验仍限制在双方真实能力交集。菜单悬停高亮、按下态及白色指针圈与相同命中区域对应；标题和按钮间隙不会误触，离开时清除高亮。

`PicoRuntimeProbe` 提供不创建 XR 会话的运行时扩展探测；设备测试可用 `-e vault-phase runtime` 获取手/手柄/模型相关扩展。探测到跟踪扩展不表示已接入手网格或官方手柄模型渲染，当前仍未实现该模型渲染通道。

### 窗口、切屏、退出与硬件信息修复

- 跟随切换与菜单点击解耦：菜单固定于 LOCAL 空间；仅真实扳机上升沿触发一次。关闭跟随时以当前头部姿态创建冻结参考空间，保留桌面位置；返回键也能关闭跟随。状态以 native 确认回调为准。
- 未收到实际视频帧的轨道不显示窗口装饰，消除只剩标题栏/抓取条的幽灵窗口。
- 窗口只保留底部灰色抓取条，命中变蓝；旁边关闭按钮仅关闭该空间窗口，“重置布局”可恢复。四角均可拖拽保持比例缩放，对角锚点固定。每个窗口使用独立 atlas 行，悬停颜色不会连带其他窗口。
- XR 使用自绘屏幕子菜单，普通窗口使用自定义 PopupWindow。已采集屏幕按 ScreenSources 映射切换本地视频轨；未采集屏幕才请求 SimpleAction 8 并等待映射。不再等待服务端 current_screen_id 必须跟随本地选择。未采集（track=-1）屏幕仍出现在菜单，超时保留会话并允许重选原屏。
- 退出先发送键/鼠标/触摸释放包，留 120ms SCTP 发送时间，然后按 UU `leave` → Socket.IO `41` → WebSocket 正常关闭退出，不立即 cancelAll。最多 2 秒后回收遗留 Socket；设备列表两次延迟刷新，避免旧 occupants 状态停留。
- 上报真实 Android SoC、内存 MiB、GPU renderer、系统默认显示模式；设备名附实际 APK 版本。UU 请求头仍保留协议兼容版本，不冒充已完成 PICO UU 被控服务。离线/不可控状态不能仅靠改硬件字段解决。

### Linux Niri 原生触摸

Linux 支持按输出命名虚拟触摸屏。支持具名 touch 配置的 Niri 可按 `OpenUUYC touch <输出名>` 独立映射；不支持该语法的版本不可直接添加具名配置。

本次用户明确允许临时改变全局映射，因此本机测试进程使用 `OPENUUYC_NIRI_TEMP_TOUCH_MAP=1`。该 opt-in 路径加载运行时临时 KDL（include 原配置 + 当前触摸输出映射），不改原文件；控制释放时恢复原配置，异常退出由看护进程恢复。**会话期间实体触摸屏也受临时全局映射影响。** 使用 `niri validate` 和 IPC reload 验证过临时配置加载/恢复，具体原生 wl_touch 手势仍需实际触控验证。

原生触摸 PB 本身没有屏幕 ID；PICO 在开始触摸前，通过同一有序通道发送已有协议的绝对定位目标（不按鼠标键），Linux 验证并保持此屏幕提示。触摸期间锁定路由，抬起/取消/断开释放触点。

XR 工具栏“输入：鼠标”可切到“输入：触摸”，扳机接触/拖动/抬起使用单指 UU 触摸 PB；普通窗口的触摸模式仍支持多触点。要测试 Linux 原生触摸，请先明确切到触摸模式，默认鼠标模式不会被错误宣传为触摸。

### 视角锚定、深度与键盘切换

- 抓住桌面底部条时，摇杆前推推远、后拉拉近；以抓取时采样的头部位置/朝向计算深度（0.45–6 米），不向远端发送滚轮事件。拖动所属手柄锁定到松开，避免另一只手接管拖动。
- 开启跟随时，在真实扳机点击的预测显示时刻采样“当前布局相对 VIEW”的姿态，再创建带此偏移的 VIEW 参考空间；不把窗口重新摆到菜单或默认头部原点。关闭时冻结当前布局空间，避免跳位。
- 菜单底部独立灰色条可拖动；菜单表面扩展为 1200×400，保留按键区与抓取区的分隔。
- “键盘”打开三模式页面：系统键盘使用 Android InputConnection；自定义键盘提供基本字母数字、编辑和方向键；全键盘追加 F1–F12、导航、修饰键、小键盘。Ctrl/Shift/Alt/Win 为锁定式修饰键，再次点击或关闭/失焦/切换模式时释放。普通窗口也有相同的自定义键盘弹层。
- 系统键盘在沉浸式 PICO 中是否由系统正确显示仍需佩戴验证；自绘键盘不依赖系统 IME 窗口可见性。自绘键盘发 PC 虚拟键，中文组合输入应使用系统 IME，不把 ASCII 键盘宣传成中文输入法。

### 内侧握持扳机、触摸焦点与空间射线

- PICO 内侧握持扳机使用 `/input/squeeze/click` 独立绑定：指向任意桌面，按下即进入抓取（无长按等待），松开结束；不用先点底部条。食指扳机仍控制远端，握持抓取不会派发远程点击；另一只手不会接管正在进行的拖动。
- 主桌面、其他桌面与自绘菜单统一以抓取时采样的用户位置为球心移动，并朝向用户；摇杆调抓取半径。系统 IME 窗口仍由 PICO 系统管理，不由本应用修改其布局。
- 触摸模式桌面焦点为白色小圆点，按下变蓝/放大；它画在本地透明装饰层，不发送额外输入。失焦、取消、离开桌面时清除。
- 未命中组件时绘制世界空间手柄射线（两米、4mm 宽）；使用真实 aim pose 与面向眼睛的 billboard 基向量，不在菜单上画假线。占用额外合成层，按运行时层数预算最多三个桌面、菜单和射线；不足时减少辅助桌面数量。

### 每屏窗口、实际比例与背景

窗口顶部显示真实会话设备别名和 ScreenSources 屏幕名：`设备名 - 屏幕名`。顶部“设置”打开位于该窗口的展开菜单，帧率/画质/码率/自动编码/光标/串流尺寸/物理分辨率/DPI 请求明确指向该屏幕 ID，并以 ACK 更新每屏设置缓存。底部菜单只保留空间/输入/背景等全局操作，不再摆放串流参数。

根据每个视频轨实际解码帧的旋转后宽高更新空间窗口比例，触摸命中、四角缩放、球面拖动及装饰同步使用该比例。最大尺寸按真实对角线 **100 英寸（2.54 米）** 计算，横屏、竖屏、方屏都不按固定16:9拉伸。

MR 默认关闭，默认全黑背景；可从全局菜单显式开启透视，或选黑/深灰/深蓝纯色背景。背景使用单独不透明合成层，关闭 MR 后不透出相机画面。目前未提供图片/全景背景导入。

虚拟屏入口位于全局菜单和每屏展开菜单，确认后走 UU 原生 CreateVirtualDisplay；远端返回错误、超时或没有新增屏幕均不显示为已创建。Linux 远端仍需自身虚拟显示驱动可用。

### 触摸懒映射的精确定义

仅开始一次实际触摸序列时检查被触摸屏幕。若当前会话已经映射此输出，直接复用，不重读配置、不 reload；目标不同才加载临时映射。菜单切屏、鼠标移动、视频帧到达均不修改 Niri 映射。手势期间锁定路由，正常结束控制恢复原配置；用户已明确允许会话期间全局触摸映射影响实体触摸屏。

### 沉浸式菜单与环境

- 主菜单采用 Linux 播放器的紧凑横向工具栏、深色面板、蓝色焦点；二级菜单为两列设置行，不再把环境控制铺在主菜单。
- 抓住菜单底部灰色拖动条后，摇杆前后调远近（0.45–6 米）；松开结束。
- 「环境」中设置 MR、透视可见度、纯色或自定义图片背景。MR 默认开启；用户选择会保存。透视可见度调节的是背景层与系统透视的混合，不是远程桌面透明度。
- 图片通过系统选择器导入，最大 16 MiB，私有保存并限制解码尺寸，等比填充。选中图片会关闭 MR，可再手动开启混合；取消选择不改背景。
- 跟随模式保存点击时布局相对头部的姿态；关闭时冻结在当前位置。右手 B 键通过 OpenXR 独立绑定关闭跟随，Android BUTTON_B 作补充。不支持 B 路径的旧运行时保留原有指针绑定。
- 这些行为已通过构建/基础回归；真实跟随点击、B 键和图片选择器在 PICO XR 内的交互仍需实机确认。

### 内置及程序生成背景

环境 → 背景库提供 10 种预设：全黑、深灰、深蓝、暮色渐变、极光、静谧星空、远山、空间网格、日落、流云。后七种由本地程序生成静态纹理，无需下载。
选择预设后关闭 MR 以便显示；仍可重新开启 MR 并调节透视混合。环境页支持重新生成图案（更换保存的随机种子），以及 25/50/75/100% 背景亮度。背景、种子和亮度随应用重启恢复，自定义图片入口保留。
生成在后台执行，缓存 768×512 位图，不在每个 XR 帧重新生成；当前是背景平面纹理，不是 360° 全景或可行走三维场景。

画质弹窗现按 Linux 播放器采用纵向预设列表、独立帧率按钮、显示器/DPI与高级设置入口；设备切换采用状态列表。未开放的 HDR/4:4:4 保持不可用提示。窗口标题条区分设备下拉、屏幕标签、画质按钮及虚拟屏新增按钮，所有请求仍受远端实际能力校验。
